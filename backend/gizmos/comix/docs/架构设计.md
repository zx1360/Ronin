# comix 架构设计

漫画下载管理系统：消费端（Northstar 网页端 / Torrid 安卓端）→ Monarch Go HTTP 服务 → 无状态 Python CLI → 单文件 SQLite + 四站适配器。

设计原则：**自用场景、易于阅读和维护优先，不做过度抽象**。Python 端所有操作
无状态（每次调用独立进程/独立数据库连接），通过 CLI + JSON 被 Go 服务调度。

## 1. 项目目录结构

```
comix/                        # Python 包（统一入口 python -m comix.cli）
├── __init__.py
├── config.py                 # 配置：数据库文件/存储根（backend/.env 或环境变量）+ 并发与稳定性
├── db.py                     # sqlite3 访问层：连接/事务 + 全部数据操作（建表 SQL 不在此处）
├── models.py                 # 轻量数据类：ComicInfo / ChapterInfo / ComicDetail
├── scheduler.py              # 调度层：搜索候选、选源、增量下载、更新检查、删除
├── cli.py                    # 无状态命令行：argparse + JSON 输入输出（Go 对接入口）
└── adapters/
    ├── __init__.py           # 适配器注册表（ADAPTERS，注册顺序即调度尝试顺序）
    ├── base.py               # BaseAdapter：通用配置/稳定性配置/HTTP/通用下载
    ├── manhuayu.py           # 漫画鱼（Playwright）
    ├── morui.py              # 摩锐漫画（纯 requests）
    ├── nicemh.py             # 奈斯漫画（Playwright）
    └── xmanhua.py            # xManga（纯 requests + packer 反混淆）
scripts/                      # 运维脚本：更新检查 / 旧资源导入 / 图片记录补齐
util/                         # 通用库：会话重试/随机头/原子下载/目录清理/宽高解析
docs/                         # 架构设计 / 对接协议 / 验收步骤
.env                          # 爬虫专用参数（并发/超时）；数据库与存储根见 backend/.env
requirements.txt
```

图片存储根由 `backend/.env` 的 `COMIC_STORAGE_ROOT` 指定（默认 Ronin 的 `_static/comics`）。

## 2. 表结构

真源：`backend/references/db/sqlite.sql`（Monarch 启动时执行，`comix init` 读同一份）。
表名统一加 `comic_` 前缀（SQLite 无 schema 概念）；各列语义见
`backend/references/db/comix.md`。

| 表 | 说明 |
|---|---|
| `comic_sites` | 站点适配器（code 唯一：manhuayu/morui/nicemh/xmanhua/legacy） |
| `comics` | 漫画（site_id+site_comic_id 唯一；存储目录 `comics/{id}`） |
| `comic_chapters` | 章节（comic_id+chapter_no 唯一；url 全局唯一；status pending/done/failed） |
| `comic_images` | 图片记录（chapter_id+sort_num 唯一；file_name/width/height） |
| `comic_download_tasks` | 下载任务（chapter_id 唯一；status queued/running/done/failed） |
| `comic_aliases` | 别名（跨站关联辅助） |

跨站去重与关联规则：同一漫画在不同站各存一行 `comics`（UNIQUE(site_id,
site_comic_id) 防同站重复）；新增漫画时按 `title_normalized` 匹配已有记录，
输出 `related_comics` 提示跨站关联；章节 URL 全局唯一，重复注册自动跳过。

> Monarch 直接读写 `comic_*` 基表，没有桥接视图：`id::text`、`dir_name`、`image_path`
> 等投影由 SQL 表达式与 Go 侧转换完成。

## 3. 适配器接口规范

```python
class BaseAdapter:
    code: str            # 站点标识
    name: str            # 站点名
    base_url: str
    # 稳定性配置（.env 提供默认，站点可覆盖）
    page_timeout_sec / img_timeout_sec / image_retry_times /
    chapter_retry_times / max_workers / strict_expected_total

    def search(self, name: str) -> list[ComicInfo]        # 站点搜索
    def get_chapters(self, detail_url: str) -> ComicDetail # 解析详情页
    def _fetch_chapter_image_urls(self, chapter_url: str) -> tuple[list[str], int]
    def download_chapter(self, chapter: ChapterInfo, save_dir: str) -> tuple[bool, int, str]
    # 通用工具：session() / headers() / get() / sleep()
```

站点只需实现 `search` / `get_chapters` / `_fetch_chapter_image_urls` 三个方法，
`download_chapter`（原子下载到 `save_dir`，失败不留残目录）在基类统一实现。
所有通用逻辑（会话重试、随机请求头、随机休眠、稳定性配置、图片下载重试、
三位页码命名、原子提交）都已下沉到 `base.py` 与 `util/common.py`，
**四个适配器文件内不再有可提取的共同逻辑**。

### 新站接入模板（最小改动）

```python
from .base import BaseAdapter
from ..models import ChapterInfo, ComicDetail, ComicInfo

class MySiteAdapter(BaseAdapter):
    code = "mysite"
    name = "我的漫画"
    base_url = "https://mysite.com/"

    def search(self, name):          # 构建搜索 URL，解析候选列表
        ...
    def get_chapters(self, detail_url):  # 解析漫画名 + 章节列表
        ...
    def _fetch_chapter_image_urls(self, chapter_url):  # 解析本章图片 URL
        ...
```

然后在 `adapters/__init__.py` 注册表中加入 `MySiteAdapter` 即可全系统生效
（搜索、调度、更新检查、存储、删除全部自动支持）。

## 4. 下载调度、候选选择与增量下载流程

```
输入漫画名
  └─ scheduler.add_comic(name)
       ├─ search_all(name)：遍历全部已启用站点适配器 search()
       │    （站点异常只记录 errors，不影响其他站）
       ├─ 候选 0 个 → NotFound
       ├─ 候选 1 个 → 直接使用
       ├─ 候选多个且未指定 --site/--pick → CandidateChoiceRequired（候选列表 JSON，
       │    由上层 Flutter/Go 展示给用户选择，不绑定 UI）
       └─ 选定后：
            get_chapters(detail_url) 解析漫画 + 章节
            ├─ 同站同漫画已存在（site_id+site_comic_id）→ 复用 comic_id，仅补登记新章节
            ├─ 写入 comics 行，rel_dir = comics/{comic_id}
            ├─ 批量写章节行（幂等，重复 URL/no 自动跳过），rel_dir 回填
            └─ download_comic（可 --no-download 只登记）
                 ├─ 增量：只取 status != done 的章节
                 ├─ --range 1-5,8 限定章节号；--latest N 取最新 N 个待下载章节
                 ├─ 并发 ThreadPoolExecutor（.env COMIX_MAX_WORKERS，默认 2）
                 └─ 每章：download_chapter 原子下载到 {存储根}/{comic_id}/{chapter_id}/
                    └─ 页码三位补齐（001.jpg），DB 只存相对路径
```

增量下载三层幂等：DB 状态 done 跳过 → 磁盘目录已有图片跳过 → 临时目录原子提交
（`.downloading` 目录 + os.replace，失败自动清理，不产生半截章节）。

## 5. 更新检查与自动全量检查

- `scheduler.check_updates(comic_id)`：调用站点 `get_chapters(detail_url)` 重拉章节
  列表，与本地 `comic_chapters.url` 集合对比（URL 全局唯一，天然去重），
  差异即为 `new_chapters`（含章节号/标题/URL）。
- `--download` 时自动登记新章节并走增量下载（同样幂等）。
- `scripts/check_updates.py [--download] [--latest N] [--json]`：遍历全部已登记
  漫画执行上述检查，可注册为 Windows 计划任务实现无人值守追更；
  `--json` 输出供 Go 服务/日志系统消费。

## 6. 无状态化与 Go 服务交互

- Python 端每次调用独立进程：`python -m comix.cli --json <command> ...`，
  无任何会话状态，可并发调用；下载并发仅限命令内部线程池。
- stdout 只输出一条 JSON（成功 `{"ok":true,"data":...}` / 业务错误
  `{"ok":false,"error":...}` 附带候选列表）；进度日志全部走 stderr；
  已强制 UTF-8 编码，Windows 管道下中文无损。
- 退出码：0 成功 / 2 业务错误（多候选、未找到）/ 1 意外异常。
- 完整命令与 JSON 字段见 `docs/协议文档.md`（含 Go 调用示例）。

## 7. 站点适配器实现要点

| code | 站点 | 解析方式 | 图片获取 | 搜索端点 |
|---|---|---|---|---|
