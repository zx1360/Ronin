# comix 架构设计

漫画下载管理系统：Flutter / ops 网页端 → 本地 Go HTTP 服务 → 无状态 Python CLI →
**单文件 SQLite**（与 Go 后端共用同一个库文件）+ 四站适配器。

设计原则：**自用场景、易于阅读和维护优先，不做过度抽象**。Python 端所有操作
无状态（每次调用独立进程/独立连接），通过 CLI + JSON 被 Go 服务调度。

`backend/static/comics`），**不在本项目目录内**。

## 2. 数据库：单文件 SQLite（与 Go 共用）

- 库文件路径：环境变量 `DB_PATH`（相对当前工作目录）优先；未设置时按
  `data/monarch.db` → `../../data/monarch.db` 的顺序取第一个已存在的文件
  （与 `backend/gizmos/internal/service/config/config.go` 同一策略）。
  Go 服务以 `cwd=backend/gizmos/comix` 拉起 CLI，因此默认命中 `../../data/monarch.db`。
- 表名扁平（SQLite 没有 schema）：原 `comix.<表>` → `comix_<表>`。
- 建表、索引、桥接视图全部由 `comix/db.py` 的 `init_db()` 幂等产出。

### 共建约定

| 约定 | 说明 |
|---|---|
| 主键 | `comix_comic` / `comix_chapter` 用 `INTEGER PRIMARY KEY AUTOINCREMENT`（id 是磁盘目录名，**永不复用**）；其余子表用 `INTEGER PRIMARY KEY`（rowid 别名） |
| 时间列 | TEXT，`2006-01-02T15:04:05.000Z`（UTC / 毫秒 / 定宽，字典序即时序）；SQLite 没有 `now()`，一律由 `comix/timefmt.now_text()` 写入 |
| 布尔列 | INTEGER 0/1（`enabled` / `is_public` / `readed`）；CLI JSON 输出时归一为 true/false |
| 外键 | 每连接 `PRAGMA foreign_keys=ON`（默认关闭），`ON DELETE CASCADE` 全依赖它 |
| 并发 | WAL + `busy_timeout=15000` + `synchronous=NORMAL`；进程内所有写操作走模块级 `threading.Lock` |
| 索引 | `idx_chapter_comic` / `idx_task_chapter` / `idx_image_chapter` + 视图表达式索引（见 §4） |

### 表结构

`comix_site` —— 站点适配器表

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK AUTOINCREMENT | 站点 ID |
| code | TEXT UNIQUE | 适配器标识：manhuayu/morui/nicemh/xmanhua/legacy |
| name | TEXT | 站点名 |
| base_url | TEXT | 站点根 URL |
| enabled | INTEGER 0/1 | 是否启用（调度时跳过禁用站点） |
| created_at | TEXT | 注册时间 |

`comix_comic` —— 漫画表

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK AUTOINCREMENT | comic_id（存储目录 `comics/{comic_id}`，永不复用） |
| title | TEXT | 漫画名 |
| title_normalized | TEXT | 归一化标题（小写去标点），跨站同名关联键 |
| site_id | INTEGER FK→comix_site | 来源站点 |
| site_comic_id | TEXT | 站内漫画标识，与 site_id 联合唯一去重 |
| detail_url | TEXT | 详情页 URL（更新检查用） |
| author / status / cover_url | TEXT | 元信息（可空） |
| total_chapters / max_chapter_no | INTEGER | 站内章节总数 / 已登记最大序号 |
| rel_dir | TEXT | 存储相对路径 `comics/{comic_id}` |
| is_public / readed | INTEGER 0/1 | 书库管理字段（Go/Flutter 可更新） |
| cover_image | TEXT | 本地封面相对路径，**显式维护**（下载/导入/backfill/sync） |
| created_at / updated_at | TEXT | 时间戳（`updated_at` 每次 UPDATE 显式写入） |

`comix_chapter` —— 章节表

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK AUTOINCREMENT | chapter_id（存储目录 `comics/{comic_id}/{chapter_id}`） |
| comic_id | INTEGER FK→comix_comic CASCADE | 所属漫画 |
| site_id | INTEGER FK→comix_site | 来源站点 |
| chapter_no | INTEGER | 站内章节顺序号（1 起；与站点一致的不变量） |
| title | TEXT | 章节名 |
| url | TEXT UNIQUE | 章节页 URL（全局唯一，更新检查/跨站去重依据） |
| page_count | INTEGER | 已下载图片数 |
| rel_dir | TEXT | 存储相对路径 `comics/{comic_id}/{chapter_id}` |
| status | TEXT | pending / done / failed |
| error | TEXT | 最近失败原因 |
| created_at / updated_at | TEXT | 时间戳 |

`comix_image` —— 图片记录表（章节下每张图一行，含宽高）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 图片行 ID |
| chapter_id | INTEGER FK→comix_chapter CASCADE | 所属章节 |
| sort_num | INTEGER | 图片序号（与文件名数字一致，`005.webp` → 5），与 chapter_id 联合唯一 |
| file_name | TEXT | 文件名：001.jpg / 005.webp |
| width / height | INTEGER | 下载/导入时解析（失败记 0） |

`comix_download_task` —— 下载任务表

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 任务 ID |
| comic_id / chapter_id | INTEGER FK CASCADE | 漫画 / 章节（chapter_id 唯一：每章一条最新任务） |
| status | TEXT | queued / running / done / failed / skipped |
| image_count | INTEGER | 下载图片数 |
| error | TEXT | 失败原因 |
| started_at / finished_at | TEXT（可空） | 起止时间 |

`comix_comic_alias` —— 别名表（跨站关联辅助）：`id` PK、`comic_id` FK CASCADE、
`name`（与 comic_id 联合唯一）。

跨站去重与关联规则：同一漫画在不同站各存一行（`UNIQUE(site_id, site_comic_id)`
防同站重复）；新增漫画时按 `title_normalized` 匹配已有记录，输出 `related_comics`
提示跨站关联；章节 URL 全局唯一，重复注册自动跳过。

## 3. 适配器接口规范

```python
class BaseAdapter:
    code: str            # 站点标识
    name: str            # 站点名
    base_url: str
    # 稳定性配置（.env 提供默认，站点可覆盖）
    page_timeout_sec / img_timeout_sec / image_retry_times /
    chapter_retry_times / max_workers / strict_expected_total

    def search(self, name: str) -> list[ComicInfo]        # 站点搜索
    def get_chapters(self, detail_url: str) -> ComicDetail # 解析详情页
    def _fetch_chapter_image_urls(self, chapter_url: str) -> tuple[list[str], int]
    def download_chapter(self, chapter: ChapterInfo, save_dir: str) -> tuple[bool, int, str]
    # 通用工具：session() / headers() / get() / sleep()
```

站点只需实现 `search` / `get_chapters` / `_fetch_chapter_image_urls` 三个方法，
`download_chapter`（原子下载到 `save_dir`，失败不留残目录）在基类统一实现。
所有通用逻辑（会话重试、随机请求头、随机休眠、稳定性配置、图片下载重试、
三位页码命名、原子提交）都已下沉到 `base.py` 与 `util/common.py`，
**四个适配器文件内不再有可提取的共同逻辑**。

把站点写入 `comix_site`。

## 4. 桥接视图与 Go 端对接

Go 端直接查询三个**只读视图**（`gizmos` 的 `comic_repo` 与主服务的 `comix_repo`），
视图把基表投影成既有客户端期望的旧结构；写操作（改 `is_public`/`readed`/`cover_image`、
删除漫画）由 Go 直接落到基表 `comix_comic`。

```sql
CREATE VIEW comix_comic_books AS
SELECT CAST(c.id AS TEXT) AS id, c.title, c.cover_image, c.is_public, c.readed
FROM comix_comic c;

CREATE VIEW comix_comic_chapters AS
SELECT CAST(ch.id AS TEXT) AS id, CAST(ch.comic_id AS TEXT) AS comic_id,
       substr('000'||ch.chapter_no, -3) || '_' || ch.title AS dir_name,
       ch.chapter_no AS chapter_index
FROM comix_chapter ch;

CREATE VIEW comix_comic_images AS
SELECT CAST(img.id AS TEXT) AS id, CAST(img.chapter_id AS TEXT) AS chapter_id,
       ch.rel_dir || '/' || img.file_name AS image_path,
       img.sort_num, img.width, img.height
FROM comix_image img
JOIN comix_chapter ch ON ch.id = img.chapter_id;
```

字段映射：

| 视图列 | 数据来源 |
|---|---|
| `comix_comic_books.id` | `comix_comic.id` 转 TEXT（"1"、"2"…，Go 端 string 透传） |
| `comix_comic_books.cover_image` | `comix_comic.cover_image`（**显式维护**，视图不做动态计算） |
| `comix_comic_books.is_public / readed` | 基表 0/1（Go 端可更新） |
| `comix_comic_chapters.dir_name` | `substr('000'||chapter_no, -3) || '_' || title`（如 `001_第1话`） |
| `comix_comic_chapters.chapter_index` | `comix_chapter.chapter_no` |
| `comix_comic_images.image_path` | `chapter.rel_dir \|\| '/' \|\| image.file_name`（相对存储根） |
| `comix_comic_images.sort_num / width / height` | 同名列 |

查询约定（Go 端现状，改表时必须保持）：

- Go 用 `CAST(c.id AS TEXT) = ?` 比较主键（入参是 TEXT），并靠
  `COALESCE(b.is_public, 1)` / `COALESCE(b.readed, 0)` 兜缺行；
- 视图 id 系列列是 `CAST(... AS TEXT)` 表达式，因此基表上建了表达式索引
  `idx_comic_id_text / idx_chapter_id_text / idx_chapter_comic_id_text /
  idx_image_id_text / idx_image_chapter_id_text`；实测
  `EXPLAIN QUERY PLAN` 走 `SCAN ch USING INDEX idx_chapter_comic_id_text`。
  **改视图表达式必须同步这些索引**（否则大表连接退化为全扫）。
- 禁止在视图里加"取第一章第一图"这类相关子查询（JOIN 放大后逐行执行会超时）。
- 删除漫画依赖 `comix_comic` 上的级联外键（Go 侧 `DELETE FROM comix_comic`），
  因此 `foreign_keys=ON` 是硬前提。

## 5. 下载调度、候选选择与增量下载流程

```
输入漫画名
  └─ scheduler.add_comic(name)
       ├─ search_all(name)：遍历全部已启用站点适配器 search()
       │    （站点异常只记录 errors，不影响其他站）
       ├─ 候选 0 个 → NotFound
       ├─ 候选 1 个 → 直接使用
       ├─ 候选多个且未指定 --site/--pick → CandidateChoiceRequired（候选列表 JSON，
       │    由上层 Flutter/Go 展示给用户选择，不绑定 UI）
       └─ 选定后：
            get_chapters(detail_url) 解析漫画 + 章节
            ├─ 同站同漫画已存在（site_id+site_comic_id）→ 复用 comic_id，仅补登记新章节
            ├─ 写入 comic 行，rel_dir = comics/{comic_id}
            ├─ 批量写 chapter 行（按站点序号让位重排，冲突如实上报），rel_dir 回填
            └─ download_comic（可 --no-download 只登记）
                 ├─ 增量：只取 status != done 的章节
                 ├─ --range 1-5,8 限定章节号；--latest N 取最新 N 个待下载章节
                 ├─ 并发 ThreadPoolExecutor（.env COMIX_MAX_WORKERS，默认 2）
                 └─ 每章：download_chapter 原子下载到 comics/{comic_id}/{chapter_id}/
                    └─ 页码三位补齐（001.jpg），DB 只存相对路径
```

增量下载三层幂等：DB 状态 done 跳过 → 磁盘目录已有图片跳过 → 临时目录原子提交
（`.downloading` 目录 + `os.replace`，失败自动清理，不产生半截章节）。

下载成功后回填 `comix_image`（含宽高）并维护 `comix_comic.cover_image`，
三者（章节状态 / 图片记录 / 封面）是 Go 端视图可见性的完整前提。

## 6. 更新检查与自动全量检查

- `scheduler.check_updates(comic_id)`：调用站点 `get_chapters(detail_url)` 重拉章节
  列表，与本地 `chapter.url` 集合对比（URL 全局唯一，天然去重），
  差异即为 `new_chapters`（含章节号/标题/URL）。
- `--download` 时自动登记新章节并走增量下载（同样幂等）。
- `scripts/check_updates.py [--download] [--latest N] [--json]`：遍历全部已登记
  漫画执行上述检查，可注册为 Windows 计划任务实现无人值守追更；
  `--json` 输出供 Go 服务/日志系统消费。

## 7. 无状态化与 Go 服务交互

- Python 端每次调用独立进程：`python -m comix.cli --json <command> ...`，
  无任何会话状态，可并发调用；下载并发仅限命令内部线程池。
- 与 Go 服务共用同一个 SQLite 文件：Go 用写池单连接写入，Python 用进程内写锁 +
  `busy_timeout` 等待；WAL 下读不阻塞写。
- stdout 只输出一条 JSON（成功 `{"ok":true,"data":...}` / 业务错误
  `{"ok":false,"error":...}` 附带候选列表）；进度日志全部走 stderr；
  已强制 UTF-8 编码，Windows 管道下中文无损。
- 退出码：0 成功 / 2 业务错误（多候选、未找到）/ 1 意外异常。
- 完整命令与 JSON 字段见 `docs/协议文档.md`（含 Go 调用示例）。

## 8. 存量数据迁移

- **PostgreSQL → SQLite（一次性，已完成）**：导入脚本与其验收步骤已移出仓库，
  归档在 `Ronin-archive/comix-pg-import/`。做法是先在 PostgreSQL 侧开只读事务
  （`default_transaction_read_only=on` + `SET TRANSACTION READ ONLY`），逐表 SELECT 后
  写入 `comix_*`（`INSERT ... ON CONFLICT (id) DO NOTHING`，id 稳定、可重复运行），
  结束时逐表比对行数，不一致即非零退出。回退 = 删除 SQLite 库文件。
- **旧爬虫资源（comics_ 目录）**：`python scripts/import_legacy.py --execute`，
  每本一个事务，失败回滚 DB + 目录回移，中断可自愈。
- **存量已下载章节缺图片记录**：`python scripts/backfill_images.py`（幂等）。

## 9. 四站脚本的归并结果

四站旧脚本的站点特有解析逻辑（章节列表 XPath、图片链接采集、packer 反混淆）落在
对应适配器；公共逻辑（会话/重试/随机头/原子下载/稳定性配置）下沉到 `base.py` 与
`util/common.py`。旧脚本以硬编码详情 URL 运行，等价入口是
`add-url <站点> <详情URL>`（或 `add <名称>` 走搜索候选流程）。
目录规范统一为 `comics/{comic_id}/{chapter_id}/{页码}.扩展名`，数据库仅存相对路径。

## 10. 站点适配器实现要点

| code | 站点 | 解析方式 | 图片获取 | 搜索端点 |
|---|---|---|---|---|
| manhuayu | 漫画鱼 | requests+lxml | Playwright（window.params.chapter_images，回退滚动采集） | /search/{关键词}/ |
| morui | 摩锐漫画 | requests+lxml | 纯 requests（内联 chapterImages + CDN 拼接） | /search/?q= |
| nicemh | 奈斯漫画 | requests+lxml | Playwright（window.params.chapter_images，回退网络响应采集） | /search?q= |
| xmanhua | xManga | requests+lxml | 纯 requests（chapterimage.ashx + packer 解码，固定桌面 UA） | /search?title= |
