# comix 漫画下载管理系统 —— 验收步骤

本文件按"数据层 → 适配器 → 调度 → 增量下载 → 更新检查 → 删除 → 全量脚本 → Go 对接"
的顺序给出可复现的验收步骤与预期效果。全部命令在本项目根目录
（`backend/gizmos/comix`）运行，使用系统 Python 3.13；数据库文件与漫画存储根
由 `backend/.env` 提供（`DB_FILE` / `COMIC_STORAGE_ROOT`）。

## 0. 环境准备（一次性）

```powershell
pip install -r requirements.txt          # requests/lxml/fake-useragent/playwright/dotenv（数据库用标准库 sqlite3）
python -m playwright install chromium    # 漫画鱼、奈斯漫画两个站点需要（已装则跳过）
python -m comix.cli init                 # 建表（读 backend/references/db/sqlite.sql）+ 注册 4 个站点
```

预期：`init` 输出 `{"ok": true, ...}`，`comic_sites` 表出现 4 行
（manhuayu 漫画鱼 / morui 摩锐漫画 / nicemh 奈斯漫画 / xmanhua xManga）。

## 1. 站点与搜索验收

```powershell
python -m comix.cli sites                          # 列出 4 个站点
python -m comix.cli search "海贼王"                # 全站搜索
```

预期：`search` 返回多站候选列表，每项含 `site`、`site_name`、`title`、
`detail_url`、`match`（exact/fuzzy）；完全同名命中排在前面。任一站搜索
接口异常只记录到 `errors` 字段，不影响其他站。

## 2. 添加与候选选择验收

```powershell
# 多候选且未指定选择 → 返回候选列表（Go 服务可据此展示给用户）
python -m comix.cli --json add "海贼王"
# → {"ok": false, "error": "存在 N 个候选...", "candidates": [...]}，退出码 2

# 指定站点 + 序号选择
python -m comix.cli --json add "海贼王" --site xmanhua --pick 0
# → 登记《海賊王》973 章，comic_id 返回，含 related_comics 跨站关联提示
```

预期：候选唯一时 `add` 直接使用；多候选时必须 `--pick`/`--site`，
机制与 Go 服务"搜索→展示→选择→添加"链路一致。

## 3. 下载与存储规范验收

```powershell
# 用已知详情 URL 直接添加并限量下载（原脚本的四部漫画）
python -m comix.cli --json add-url manhuayu https://www.manhuayu88.com/8375 --latest 3
python -m comix.cli --json add-url morui     https://www.morui.com/comic/1165/   --latest 3
python -m comix.cli --json add-url nicemh    https://www.nicemh.com/manhua/jdQYMxoQnV --latest 3
python -m comix.cli --json add-url xmanhua   https://www.xmanhua.net/335xm/      --latest 3
```

预期（四站一致）：
- 返回 `comic_id`、`total_chapters`、`download.downloaded` 列表；
- 磁盘目录严格为 `{COMIC_STORAGE_ROOT}/{comic_id}/{chapter_id}/001.jpg`（页码三位补齐，
  扩展名保留源格式）；数据库 `comic_chapters.rel_dir` 只存相对路径（`comics/...`）；
- 章节并发数为 `.env` 的 `COMIX_MAX_WORKERS`（默认 2），失败章节自动重试一轮。

检查存储：

```powershell
python -m comix.cli list            # 每部漫画的登记/已下载/失败章节数
python -m comix.cli chapters 1      # 章节状态与 rel_dir
```

## 4. 增量下载验收

```powershell
# 只下第 1 章，再下最新 3 章（未下章节保持 pending）
python -m comix.cli download 2 --range 1
python -m comix.cli download 2 --latest 3
# 再次执行相同命令（应全部"跳过"，无重复下载）
python -m comix.cli download 2 --latest 3
```

预期：第二次执行 `downloaded` 为空或全部 `已存在，跳过`，
`chapters` 显示已完成章节 `status=done`，未下载章节 `pending`；
重复运行不产生重复文件、不重复请求图片。

## 5. 连载更新检查验收

```powershell
python -m comix.cli update-check --comic-id 2          # 无新章节 → 报告 new_chapters 为空
python -m comix.cli update-check --all                 # 检查全部
python scripts/check_updates.py                        # 独立脚本，可加 --download 自动追更
```

模拟"站点发布新章节"后检测（任选一部漫画）：

```powershell
# 删除最新一章的本地记录（模拟本地落后于站点）
# 假设 comic 2 最新为第 N 章：DELETE 后 update-check 应报告该章为新章节
python -m comix.cli update-check --comic-id 2 --download --latest 1   # 自动补下
```

预期：`new_chapters` 列出站点有而本地没有的章节（按 URL 去重）；
`--download` 时自动登记并增量下载，且已存在于磁盘的章节幂等跳过。

## 6. 删除验收

```powershell
python -m comix.cli delete 1            # 删除漫画 1：DB 记录（章节/任务级联）+ 本地文件
python -m comix.cli list                # comic 1 消失
Test-Path "$env:COMIC_STORAGE_ROOT\1"   # → False（文件已删）
python -m comix.cli delete 1            # 再删 → {"ok": false, "error": "漫画 1 不存在"}
```

`--keep-files` 变体：只删 DB 记录，保留存储根下的文件。

## 6.5 孤儿回收验收（进程被中断后的自愈）

```powershell
# 人为制造中断残留：下载中途 kill（或用任务管理器结束 python 进程）
python -m comix.cli download 2 --latest 5    # 下载启动后立即 Ctrl+C / kill
# 此时会残留：comic_download_tasks 中 running 任务 + 存储根下的 xxx.downloading 目录

python -m comix.cli clean                     # 全局回收
# → {"ok": true, "data": {"recovered_tasks": N, "removed_temp_dirs": N}}
python -m comix.cli chapters 2                # running 任务已变为 failed
# 或直接重新下载：download 命令会自动回收当前漫画的残留
python -m comix.cli download 2 --latest 5     # 自动清理残留并正常重下
```

预期：中断残留不会永久遗留；重下前自动清理 `.downloading` 半截目录并重新下载，
最终章节 `done`、无 `running` 残留。

> 说明：`comic_chapters` 表大量 `pending` 属正常（登记即入库，下载才置 `done`）；
> `--no-download` 只登记时磁盘目录不创建（懒创建）。

## 7. 全量更新脚本验收

```powershell
python scripts/check_updates.py --json           # 全部漫画检查报告（JSON，供计划任务/Go 服务）
python scripts/check_updates.py --download       # 检查并自动增量下载全部新章节
```

预期：遍历所有已登记漫画，逐部输出 `latest_site_no` / `local_max_no` /
`new_chapters`；`--download` 时自动补下；脚本可注册为 Windows 计划任务
实现无人值守追更（退出码 0 成功、2 无漫画）。

## 8. Go 服务对接验收（协议见 docs/协议文档.md）

```go
cmd := exec.Command("python", "-m", "comix.cli", "--json", "list")
cmd.Dir = "<backend/gizmos/comix>"
out, err := cmd.Output()   // stdout 单行 JSON，日志在 stderr
```

> Monarch 调用时会注入 `MONARCH_DB_FILE` 与 `COMIC_STORAGE_ROOT`（取自 backend/.env），
> 独立运行时 `config.py` 自行回退加载 backend/.env。

预期：任意命令 `stdout` 只有一条 JSON；`--json` 模式下无进度噪音；
Windows 控制台管道下输出仍为 UTF-8（中文标题完好）。
