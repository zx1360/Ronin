# comix 命令契约

Monarch 在 comix 根目录调用 `python -m comix.cli --json <command>`。参数以 [cli.py](../comix/cli.py) 或 `--help` 为准，Go 调用见 [service/comix](../../../internal/service/comix/)。

stdout 是一条 UTF-8 JSON，进度和告警走 stderr。退出码 0 返回 `{"ok":true,"data":...}`，2 返回 `{"ok":false,"error":...}`（多候选时附 `candidates`），1 表示意外异常。任务结果保留业务错误与进程错误的区别。

| 命令 | 结果与行为 |
| --- | --- |
| `search` | 返回 `candidates`（含 `site`、`detail_url`、`match`）和各站 `errors`。exact 优先。 |
| `add` / `add-url` | 按搜索候选或详情 URL 登记。多候选通过 `--site` / `--pick` 选择。同站同漫画复用 `comic_id`，`already_exists` 表明已有记录，`related_comics` 提示跨站同名。下载结果嵌在 `data.download`。 |
| `download` | 处理待下载与缺图章节，按 `--range` 或 `--latest` 过滤。失败章节自动再试一轮，结果分为 `downloaded`、`failed`。 |
| `update-check` | `reports` 逐部给出本地进度、按 URL 识别的 `new_chapters` 和站点错误。加 `--download` 处理新章节与 pending，failed 只提示。 |
| `delete` | 默认删除记录和文件。CLI 的 `--keep-files` 仅删记录。 |
| `clean` | 回收全局 running 残留与 `.downloading` 目录。下载前也会回收本漫画的残留。 |

查询字段以仓库层代码为准。计划追更入口为 [scripts/check_updates.py](../scripts/check_updates.py)，用 `--help` 查看选项。站点线路用 `COMIX_<CODE>_ROUTE`，页面与图片共用 `system`、`direct` 或代理地址。
