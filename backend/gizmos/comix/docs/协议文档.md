# comix 对接协议文档（Go HTTP 服务 → Python CLI）

本文件定义本地 Go HTTP 服务调用 comix Python 端的协议：调用方式、命令参数、
JSON 输入输出格式、退出码与错误处理。消费端（Northstar 网页端 / Torrid 安卓端）
只与 Go 服务通信，Go 服务通过子进程调用本 CLI 完成搜索、下载、更新检查、删除等操作。

## 1. 调用方式

Go 服务以子进程方式调用本地 Python 解释器（不打包 exe）：

```go
cmd := exec.Command("python", "-m", "comix.cli", "--json", "search", "海贼王")
cmd.Dir = "<backend/gizmos/comix>"   // 必须在项目根目录运行（依赖 .env 与 util 包）
out, err := cmd.Output()          // stdout 即完整 JSON
```

- 每次调用都是独立进程、独立数据库连接，**无任何状态残留**，可并发调用；
  下载类命令自身内部并发（每章一个线程），Go 侧无需加锁，但建议对同一
  漫画的写操作串行化（由业务层控制）。
- 数据库文件与漫画存储根由 backend/.env 统一持有，Monarch 调用时注入
  `MONARCH_DB_FILE` / `COMIC_STORAGE_ROOT` 环境变量；独立运行时 `config.py`
  回退加载 backend/.env，本项目 `.env` 只放爬虫参数（并发/超时）。
- stdout 只输出一条 JSON（一行），供 `cmd.Output()` 直接解析；
  所有进度日志（下载过程、警告）输出到 stderr，不影响 JSON。
- CLI 已强制 stdout/stderr 使用 UTF-8 编码，中文标题无乱码。

## 2. 统一响应格式

### 成功

```json
{"ok": true, "data": { ...命令相关字段... }}
```

### 业务错误（如未找到、多候选未选择）

```json
{"ok": false, "error": "错误描述", "candidates": [ ...可选的候选列表... ]}
```

退出码：`0` 成功；`2` 业务错误（可在 data/candidates 中继续处理）；
`1` 意外异常（stderr 有堆栈）。

## 3. 命令一览

| 命令 | 作用 | 关键参数 |
|---|---|---|
| `init` | 建表并注册站点 | 无 |
| `sites` | 列出可用站点 | 无 |
| `search <名称>` | 全站搜索候选 | 无 |
| `add <名称>` | 搜索并添加漫画（可选下载） | `--site`/`--pick`/`--no-download`/`--range`/`--latest` |
| `add-url <站点> <详情URL>` | 按 URL 直接添加 | 同上 |
| `list` | 列出已登记漫画 | 无 |
| `chapters <comic_id>` | 查看章节状态 | 无 |
| `download <comic_id>` | 增量下载 | `--range 1-5,8` / `--latest N` / `--no-retry-failed` |
| `update-check` | 连载更新检查 | `--comic-id` / `--all` / `--download` / `--latest` |
| `delete <comic_id>` | 删除漫画 | `--keep-files` |
| `clean` | 回收中断残留（running 任务 + .downloading 临时目录） | 无 |

所有命令均需带 `--json` 参数（Go 服务调用时）。

## 4. 关键命令详细说明

### 4.1 搜索：`search <名称>`

```json
{"ok": true, "data": {
  "keyword": "海贼王",
  "candidates": [
    {"title": "海贼王", "detail_url": "https://www.xmanhua.net/139xm/",
     "site_comic_id": "139xm", "author": "", "status": "", "cover_url": "",
     "match": "exact", "site": "xmanhua", "site_name": "xManga"}
  ],
  "errors": {}   // 各站搜索异常信息，键为站点代码
}}
```

`match`：`exact`（标题完全一致）或 `fuzzy`。每站最多返回 10 条，exact 优先。
`site` 是适配器代码（`manhuayu`/`morui`/`nicemh`/`xmanhua`），跨站调度的唯一标识。

### 4.2 添加漫画：`add <名称>`

多候选选择协议（核心）：

1. Go 服务先调用 `search`，把候选展示给用户（Flutter UI）；
2. 用户选定后调用 `add <名称> --site <site> --pick <N>` 或只 `--pick <N>`；
3. 若候选唯一，`add` 直接使用该候选，无需 pick。

若直接 `add` 且存在多个候选，返回：

```json
{"ok": false, "error": "存在 N 个候选，需要指定 --pick 或 --site",
 "candidates": [ ...同 search 格式... ]}
```

成功响应：

```json
{"ok": true, "data": {
  "comic_id": 1, "title": "鬼畜英雄", "site": "morui",
  "site_name": "摩锐漫画", "detail_url": "https://www.morui.com/comic/1165/",
  "rel_dir": "comics/2", "total_chapters": 121,
  "already_exists": false,
  "related_comics": [{"comic_id": 3, "title": "鬼畜英雄", "site": "nicemh"}],
  "download": { ...见 4.3... }
}}
```

- `already_exists`：同站同漫画已登记时复用记录（并补登记新章节）。
- `related_comics`：跨站同名已登记的漫画（跨站关联提示）。
- `download`：仅当未传 `--no-download` 时出现，结构见 4.3。
- 需要迁移已知链接时用 `add-url`（跳过搜索，直接按详情 URL 解析）。

### 4.3 下载：`download <comic_id>`

```json
{"ok": true, "data": {
  "comic_id": 1, "title": "鬼畜英雄",
  "downloaded": [
    {"chapter_id": 18, "chapter_no": 1, "title": "第1话",
     "ok": true, "pages": 24, "rel_dir": "comics/2/18", "error": ""}
  ],
  "failed": [
    {"chapter_id": 20, "chapter_no": 3, "title": "第3话",
     "ok": false, "pages": 0, "rel_dir": "comics/2/20", "error": "图片下载失败: ..."}
  ],
  "skipped": 0, "message": ""
}}
```

- 增量语义：只下载状态非 `done` 的章节；已完成的章节天然跳过。
- `--range 1-5,8,10-12`：限定章节号区间；`--latest N`：只取最新 N 个待下载章节。
- 失败章节自动整体重试一轮（两次机会），仍失败则标记 `failed`，
  再次运行 `download` 会重试 failed 章节。

### 4.4 更新检查：`update-check`

```json
{"ok": true, "data": {"reports": [
  {"comic_id": 2, "title": "鬼畜英雄", "site": "morui",
   "latest_site_no": 125, "local_max_no": 121,
   "local_registered": 121, "local_downloaded": 121,
   "local_pending": 0, "local_failed": 0,
   "new_chapters": [{"chapter_no": 122, "title": "第122话", "url": "..."}],
   "error": ""}
]}}
```

- 不传参数时无漫画需用 `--all` 检查全部；`--comic-id` 检查单部。
- 加 `--download` 自动登记并增量下载：**既包括本次发现的新章节，也包括本地
  已登记但从未下载（`pending`）的章节**（追更语义＝把本地补齐到站点状态）。
  `failed` 章节不会自动重试，只在 `message` 中提示可重试。
  此时 report 额外含 `download_targets`（本次纳入下载的章节数）与 `download` 字段。
- `new_chapters` 按 URL 去重（站内新增章节 URL 未在本地即视为新章节）。
- `message` 始终给出本地实际下载进度（`本地已下载 X/Y 章`，并标注未下载/失败数），
  不应只凭"已是最新"判断整本已入库。

### 4.5 删除：`delete <comic_id>`

```json
{"ok": true, "data": {"comic_id": 2, "title": "鬼畜英雄",
  "files_removed": true, "rel_dir": "comics/2"}}
```

默认同时删除 DB 记录（章节/任务级联）与本地文件；`--keep-files` 仅删记录。

### 4.6 列表/章节：`list`、`chapters`

`list` 返回每部漫画的登记与下载统计（`downloaded`/`failed` 计数）；
`chapters <comic_id>` 返回全部章节及其状态（`pending`/`done`/`failed`）与
存储相对路径 `rel_dir`。

### 4.7 孤儿回收：`clean`

下载进程被 kill/断电中断时可能残留 `running` 任务与 `*.downloading` 临时目录
（图片下载到一半未提交）。`clean` 一次性回收全部：

```json
{"ok": true, "data": {"recovered_tasks": 2, "removed_temp_dirs": 2}}
```

`download` 命令每次执行前也会自动回收**当前漫画**的残留（running 任务标记为
failed + 删除该漫画下 `.downloading` 目录），因此正常使用下残留自愈；
`clean` 用于手动全局清理。

注意：`chapter` 表大量 `pending` 状态属正常——登记即入库、下载才置 `done`；
`--no-download` 只登记不下载时磁盘目录不创建（懒创建，首次下载章节时生成）。

## 5. 存储规范（Go 服务需知晓）

- 图片统一存放于 `{COMIC_STORAGE_ROOT}/{comic_id}/{chapter_id}/{页码}.{扩展名}`，
  页码三位补齐（`001.jpg`、`002.jpg`…；超 999 张自然扩展为四位）；
  `comic_id`/`chapter_id` 均为数据库主键。
- 数据库仅保存相对路径 `rel_dir`（如 `comics/2/18`，`comics/` 前缀对应存储根本身）；
  存储根由 backend/.env 的 `COMIC_STORAGE_ROOT` 指定。
- 扩展名保留源格式（jpg/webp/png），绝大多数为 jpg。

## 7. 定时全量更新

`python scripts/check_updates.py [--download] [--latest N] [--json]`
遍历全部已登记漫画检查更新，可加 `--download` 自动追更；
可直接由系统计划任务/Go 服务定时触发。
