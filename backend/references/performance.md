# 后端空闲资源占用

Monarch 是 HTTP 与任务调度进程；Gallery CLI、comix、Python AI 侧车和 Ollama 是按需调用的外部执行者。五种 AI 能力没有直接把神经网络载入 Go 服务。空闲占用需要分别检查 Go 堆、SQLite 分配的内存和子进程，不能只看 Go heap profile。

## 原因与处理

| 来源 | 处理 |
| --- | --- |
| SQLite 的 `cache_size=-65536` 按连接分配，读池保留 4 个空闲连接，查询后缓存继续驻留 | 改为每连接 8 MiB 的缓存目标，保留 1 个空闲读连接，读连接空闲 1 分钟后关闭；仍允许 8 个并发读连接 |
| 工作区关闭自动重排时同时注释了调度间隔，补队列持续每 5 秒扫描媒体与任务表 | 恢复首次 5 秒、有新增或错误时 1 分钟、无新增时 10 分钟的间隔；保留不自动重排已有任务的行为 |
| 空队列仍先检查 Python/Ollama 依赖 | 先检查待处理任务，再检查执行条件 |
| 服务启动及每 5 分钟遍历存储目录，包含 Gallery 根目录和再次遍历的预览/缩略图目录 | 改为首次访问概览时统计；5 分钟后有访问才异步刷新，同一目录并发访问共用一次扫描 |
| 7 万条向量在一次检索后一直驻留，加载过程还反复扩容并复制 | 按实际条数预分配，串行化索引加载；复用现有 worker，按 `idle_timeout_seconds` 回收向量、pHash 和非重复标记缓存 |
| 丢弃大索引后 Go 仍可能保留大量堆页 | 只有实际回收缓存时调用一次 `debug.FreeOSMemory`；普通空闲轮询不触发 GC |

SQLite 的缓存参数是缓存目标，临时结构和驱动分配不受它完全约束。以上修改不设全进程硬内存上限，不改变 WAL、事务、外键、数据库结构或现有检索算法。[SQLite 缓存说明](https://www.sqlite.org/pragma.html#pragma_cache_size)。

## 对照实测

2026-10-14，Windows x64、Go 1.26rc1、同一只读备份快照：70,010 个媒体、70,010 条 768 维向量、350,050 条任务。测试引擎保持暂停，Ollama 使用回环测试替身，Python 推理不运行；不改动生产数据库。

| 指标 | 原工作区 | 修改后 |
| --- | ---: | ---: |
| 4 个并发状态查询完成后的工作集（第 20 秒） | 655.4 MiB | 36.4 MiB |
| 同时刻 Windows PrivateMemorySize | 781.7 MiB | 74.3 MiB |
| 查询结束后的第 10–20 秒新增 CPU 时间 | 3.91 秒 | 0 秒（采样精度内） |
| 向量加载耗时 | 370 ms | 221 ms |
| 向量加载后的 Go runtime Sys，非工作集 | 304.1 MiB | 148.6 MiB |
| 连续 5 次队列统计 | 246 ms | 232 ms |

这是并发状态查询后的压力场景，不等同于原应用日常的 120–140 MB，也不代表所有机器的固定占用。实际 HTTP 服务还包括 Gin、TLS、mDNS、日志及按请求载入的数据。

另以 5 秒空闲阈值加速验收索引回收：装载 70,010 条向量后工作集约 179.7 MiB，回收后约 47.4 MiB；Go HeapAlloc 从 108.5 MiB 降至 0.5 MiB，CPU 累计仅增加约 16 ms。生产默认沿用现有 120 秒阈值，worker 最多再延迟 5 秒检查。没有访问时不维护搜索索引，状态查询不延长驻留；下次搜索会重新加载，代价是首次检索多一次装载。

首次打开存储概览仍需要统计真实目录，大目录的首次响应可能较慢；后续访问返回缓存快照，过期刷新在后台完成。后台扫描线程仅在请求触发的刷新期间存在。

## 验收与数据保护

- 在两个 Go module 中执行 `go build ./...`、`go vet ./...`、`go test ./...`。
- 覆盖补队列幂等、旧任务保持原状、空队列不探测外部依赖、回收后搜索结果一致、并发连接回收、目录缓存并发首读与过期刷新。
- 数据层验收通过只读连接 `VACUUM INTO` 创建含 WAL 已提交数据的临时副本，写入、重生成及回滚测试仅操作副本。
- 网页冒烟使用回环测试 HTTP 服务、全新临时数据库和配置，逐页、逐标签检查；不广播 mDNS、不访问生产服务。
- 性能采样程序和数据库快照在验收后清理。生产数据库、配置、媒体与正在运行的进程不作变更。

本机未配置 C 编译器且 `CGO_ENABLED=0`，未运行 Go race detector；已运行真实并发场景的回归测试。
